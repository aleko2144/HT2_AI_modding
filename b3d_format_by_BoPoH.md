# Формат .b3d (King 8.2 / Rig'n'Roll)

Формат файлов моделей и сцен игры King 8.2 (Rig'n'Roll).

## Соглашения

| Обозначение | Размер | Что это |
|---|---|---|
| `int` | 4 | int32 little-endian |
| `float` | 4 | float32 |
| `vec3` | 12 | 3 x float |
| `sphere` | 16 | центр (vec3) + радиус (float), bounding-сфера блока |
| `vec4` | 16 | 4 x float (плоскость: нормаль + d) |
| `matrix` | 48 | 4 x vec3: right, front, up, pos |
| `name` | 32 | строка cp1251, дополнена нулями |

"Ссылка" - поле `name` с именем другого блока или ресурса. Разрешается после
загрузки через общий реестр имён, пустая строка -
ссылки нет. Каждый блок с непустым именем сам регистрируется в этом реестре.

## Структура файла

### Заголовок

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | char[4] | сигнатура `b3d\0` (загрузчик не проверяет) |
| 0x04 | int | размер файла в DWORD |
| 0x08 | int | смещение секции материалов в DWORD |
| 0x0C | int | размер секции материалов в DWORD |
| 0x10 | int | смещение секции блоков в DWORD |
| 0x14 | int | размер секции блоков в DWORD |

Игра использует только два смещения. Поля связаны так:
`матOffset + матSize = blockOffset`, `blockOffset + blockSize = размер файла / 4`.

### Секция материалов

```
int   count
name  materials[count]
```

Здесь только имена. Свойства материалов (текстура, цвет, флаги) берутся из
одноимённого .res модуля. Индексы материалов в блоках - номера в этом списке.

### Секция блоков

```
int 111                       // начало секции
повторять:
    [int 444 ...]             // одиночные 444 между блоками верхнего уровня пропускаются
    int 333                   // начало блока
    <блок>
    int 555                   // конец блока
int 222                       // конец секции
```

### Маркеры

| Значение | Смысл |
|---|---|
| 111 | начало секции блоков |
| 222 | конец секции блоков |
| 333 | начало блока |
| 444 | конец списка детей |
| 555 | конец блока |

### Заголовок блока

```
name  name     // имя блока
int   type     // файловый тип (таблица ниже)
<поля типа>
```

### Списки детей

Контейнеры хранят детей в одном или нескольких списках. Перед детьми в поля
типа входит `int childCount` - общее число детей во всех списках. Число
списков задано типом блока или отдельным полем (у типов 21 и 29).

```
для каждого списка:
    повторять: int 333, <блок>, int 555
    int 444                   // конец списка
```

Правила чтения:

* Перед каждым чтением маркера: если `childCount` уже исчерпан и текущий
  список последний, чтение заканчивается без маркера. Поэтому у последнего
  списка закрывающего 444 обычно нет.
* Пустой список в середине - одиночный 444.
* Если детей прочитано не столько, сколько заявлено, блок не загружается.
* У типа 2 (BSP-узел) средний список (номер 1) в файле не записан вовсе.

Дочерний блок 6/36 без детей в списке 0 при загрузке отбрасывается.

### 0 - служебная запись

```
byte[44]
```

Игра пропускает. Допустим только на верхнем уровне. В каждом файле игры одна
такая запись с пустым именем: 11 float, все нули, кроме десятого (1.0).

### 1 - наблюдатель комнаты

```
name  space    // ссылка на space
name  room     // ссылка на комнату, либо "roomA:roomB"
```

Только на верхнем уровне, блок в дерево не попадает. Если в `room` есть `:`,
строка делится на два имени, иначе это ссылка.

### 2 - BSP-узел

```
sphere bound
vec4   splitPlane    // нормаль + d
int    childCount
lists[3]             // 0 - перед плоскостью, 1 - не записан, 2 - за плоскостью
```

Рисует сначала дальнюю от камеры сторону.

### 3 - группа с сортировкой

```
sphere bound
int    childCount
list
```

Каждый кадр сортирует детей от дальних к ближним (для прозрачных объектов).

### 4 - группа в space

```
sphere bound
name   space         // ссылка на блок 24: матрица для детей
name   collision     // ссылка на упрощённую модель коллизии
int    childCount
list
```

### 5 - группа

```
sphere bound
name   param
int    childCount
list
```

Вид блока выбирается по началу имени, поле `param` трактуется по-разному:

| Имя | Что за блок | `param` |
|---|---|---|
| `env*` | зона тумана и ambient (как 39) | текст `"fogStart fogEnd colorIndex ambient"`, по умолчанию 300 / 3000 / 8 / 0.3 |
| `lamp*` | источник света (как 33) | ключевое слово типа света: `direction` / `direct`, `position`, `spot` |
| остальное | обычная группа | ссылка на модель коллизии |

Для `lamp*` направление света - вниз, внутренний угол 45 градусов, затухание
`1 / радиус^2` (для направленного - без затухания). Группы с именем `noz*`
рисуются без записи в z-буфер.

### 6, 36, 7, 37 - меш (хранилище вершин)

```
sphere bound
name   space          // только 6 и 36: ссылка на блок 24
name   collision      // ссылка на модель коллизии
int    format         // только 36 и 37
int    vertexCount
vertex[vertexCount]
int    childCount
list
```

`format`: младший байт - режим вершин, биты 8 и выше - число дополнительных
UV-наборов (`uvExtra`). У 6 и 7 формата нет: режим 0, `uvExtra` = 0.

Вершина:

```
vec3   pos
float  u, v
float  uvExtra[uvExtra][2]
<по режиму>
```

| Режим | Дополнение вершины | Как рисуется |
|---|---|---|
| 0 | ничего | освещение задают грани детей (тип 8/35 с массивом граней) |
| 1 | vec3 цвет RGB | светится заданным цветом, лампы не влияют |
| 2 | vec3 нормаль | освещается лампами |
| 3 | float яркость | светится с заданной яркостью, лампы не влияют |

Если в настройках рендера игры выключена опция `intensity`, режим 2 при загрузке
превращается в 3: нормали запекаются в яркость по фиксированному направлению.

Сам меш ничего не рисует. Вершины передаются детям (блоки 8/35), те хранят
индексы и материалы. Несколько детей - несколько кусков с разными материалами
на общем наборе вершин.

### 8, 35 - грани меша

```
sphere bound
int    mode           // только 35
int    material       // только 35
int    count
<данные>
```

У типа 8 `mode` = 0, материала на блок нет.

| `mode` | Данные |
|---|---|
| 0 | массив граней `face[count]` |
| 1 | массив треугольников, собираются в один буфер и освещаются лампами (без опции рендера `intensity` - как 2) |
| 2 | массив треугольников, собираются в один буфер с запечённым цветом |
| 3 | `count` треугольников по 32 байта: 20 байт не используются, затем 3 x int индекса вершин |

В режимах 1 и 2 у каждой грани ровно 3 вершины, а бит 0x1 всех граней должен
совпадать с режимом: в режиме 1 все грани освещаемые, в режиме 2 все
неосвещаемые. Иначе у грани нет нужного буфера и сборка читает пустой
указатель.

`mode` 3 работает только под мешем 36/37 с режимом вершин 1, 2 или 3:
освещение треугольников целиком задаёт режим родителя.

Грань:

```
int    format
float  intensity      // яркость всей грани
int    detail         // порог детализации
int    material
int    vertexCount
для каждой вершины:
    int    index      // в массиве вершин родителя
    float  uv[layers][2]        // если format & 0x2
    vec3   normal               // если format & 0x10, освещаемая и format & 0x20
    float  intensity            // если format & 0x10, не освещаемая и format & 0x20
```

Биты `format` грани:

| Бит | Смысл |
|---|---|
| 0x1 | **инвертирован**: в файле стоит - грань не освещается (запечённый цвет), снят - освещается лампами |
| 0x2 | UV лежат в грани (иначе берутся из вершин родителя) |
| 0x4 | обратный порядок обхода (cull) |
| 0x10 | своё значение на каждую вершину (нормаль или яркость) |
| 0x20 | эти значения лежат в файле; иначе нормали берутся у родителя (меш режима 2) |
| 0x80 | triangle strip, иначе fan |
| 0xFF00 | число дополнительных UV-слоёв; при 0x2 в файле `layers` = это число + 1 |

Освещаемая грань получает нормали. Неосвещаемая получает цвет: белый для
текстурного материала или цвет палитры, умноженный на `intensity` грани (или
на яркость вершины при 0x10 и 0x20). Такая грань светится независимо от ламп.

`detail`: значение >= 0 - грань рисуется, пока детализация ниже порога;
значение < 0 - порог по дальности.

### 9, 10, 11, 22 - LOD-переключатель по объёму

```
sphere bound
<объём>
int    childCount
lists[2]       // 0 - камера внутри объёма (близко), 1 - снаружи (далеко)
```

| Тип | Объём |
|---|---|
| 9, 22 | `vec4` плоскость; "внутри" - положительное полупространство |
| 10 | `vec4` сфера: центр + радиус |
| 11 | цилиндр: `vec3 center`, `vec3 axis`, `float halfLength`, `float radius` |

Переключение - проверка положения камеры, без порога расстояния.

### 12-17, 20, 23 - примитивы коллизии

Общий хвост `params`:

```
int   flags
int   param
int   valueCount
int   values[valueCount]
```

| Тип | Форма | Поля |
|---|---|---|
| 12 | плоскость | `sphere bound`, `vec4 plane`, `params` |
| 13 | без формы | `sphere bound`, `params` |
| 14 | сфера | `sphere bound`, `vec4 sphere`, `params` |
| 15 | сфера, "внутри" = снаружи | `sphere bound`, `vec4 sphere`, `params` |
| 16 | цилиндр | `sphere bound`, `vec3 center`, `vec3 axis`, `float halfLength`, `float radius`, `params` |
| 17 | цилиндр, "внутри" = снаружи | как 16 |
| 20 | ломаная | `sphere bound`, `int pointCount`, `params`, `vec3 points[pointCount]` |
| 23 | выпуклые грани | `params`, `int faceCount`, грани: `int pointCount`, `vec3 points[pointCount]` |

Порядок полей у 20 и 23 отличается от остальных: `params` идёт раньше формы,
а у 23 нет `bound`.

Ломаная (20) с именем `way*` - дорога. Блок в дерево не попадает: из него
строится дорога комнаты, `params.flags` - флаги дороги, `values[0]` как float -
ширина (по умолчанию 10.0). Дорога должна лежать внутри комнаты (тип 19/41).

### 18 - экземпляр модели

```
sphere bound
name   space      // ссылка на блок 24: где стоит
name   model      // ссылка на блок-модель: что стоит
```

Ставит одну модель (например, `STOS`) в точку, заданную блоком 24. Одна модель
может стоять во многих местах.

### 19 - комната

```
int    childCount
list
```

Без `bound`. Корень для дорог (`way*`).

### 21 - переключатель вариантов

```
sphere bound
int    listCount
int    activeList     // какой список виден при загрузке
int    childCount
lists[listCount]
```

Виден и участвует в коллизии только один список. Номер меняет код игры.

Если имя начинается с `refer`, всё начиная с 7-го символа - имя другого
блока 21. Номер видимого списка берётся у него, свой `activeList` тогда не
используется. Так один блок переключает варианты во многих моделях сразу.

Блоки `ILLUM_LEVEL_00`..`ILLUM_LEVEL_15` (в `COMMON.B3D`, два пустых списка)
переключает смена суток: список 0 днём, 1 ночью. Модели ссылаются на них
через `refer_ILLUM_LEVEL_xx`.

### 24 - система координат (space)

```
matrix m
int    mode     // 0 - матрица абсолютная, 1 - относительно родителя
int    childCount
list
```

На space ссылаются блоки 4, 6, 36, 18 и тип 1. Код игры может менять матрицу
(анимация, двери, колёса).

### 25 - источник звука

```
int    frequency
int    mode        // 0 - без позиции, 1 - по направлению, 2 - точка с затуханием, 3 - конус
int    flags       // читается, не используется
name   sound       // ссылка на звуковой ресурс
vec3   position
vec3   direction
float  coneInner   // радианы, режим 3
float  coneOuter
float  minDistance // режимы 2, 3: до этого расстояния полная громкость
float  maxDistance // дальше - тишина
float  volume
```

Без `bound`.

### 26 - группа с заданным AABB

```
sphere bound
vec3   unused
vec3   min
vec3   max
int    childCount
list
```

Bounding-сфера пересчитывается из AABB.

### 27 - спрайт

```
sphere bound
int    flags      // бит 0 снят - позиция проецируется камерой; flags >> 1 - точка привязки 0..8
vec3   position
int    material
```

### 28 - свечение

```
sphere bound
vec3   position
int    count
element[count]
```

Элемент - плоский контур, развёрнутый к камере:

```
int    flags         // 0x2 - есть UV-кольца, 0x100 - полностью к камере; flags >> 8 - число колец
int    unused
int    unused
int    material
int    pointCount
для каждой точки:
    float  x, y
    float  ring[rings][2]    // если flags & 0x2; rings = (flags >> 8) + 1
```

### 29 - LOD по дальности

```
sphere bound
int    levelCount
int    flags          // & 0x3 - метрика (0 - глубина, 1 - экранный размер, 2 - плоскость), & 0x8 - кроссфейд
vec4   origin         // опорная точка
float  distance[levelCount]
int    childCount
lists[levelCount]     // по списку на уровень
```

### 30 - портал между комнатами

```
sphere bound
name   link
vec3   start
vec3   end
```

`start` и `end` - диагональ прямоугольника портала, вертикального или
горизонтального. `link`:

* имя блока - через портал рисуется эта соседняя комната; блок с именем
  `mirror*` - зеркало;
* `"roomA:roomB"` - портал не рисуется, при пересечении игра получает
  переход между комнатами.

### 31 - спрайт с масками по дальности

```
sphere bound
int    maskCount
vec4   anchor        // позиция + размер
int    flags         // как у 27
vec3   position
для каждой маски:
    float distance
    int   maskId
```

### 33 - источник света

```
sphere bound
int    emitsLight
int    hidden
int    lightType      // 0 - нет, 1 - направленный, 2 - точечный, 3 - прожектор
vec3   position
vec3   direction
float  attenuation0, attenuation1, attenuation2
float  intensity
float  innerCone      // радианы, не больше pi
float  outerConeDelta // innerCone + delta не больше pi
float  r, g, b
int    childCount
list
```

Свет действует только на собственных детей.

### 34 - облако точек коллизии

```
sphere bound
int    unused
int    count
повторять count раз:
    vec3  point
    int   tag       // тип поверхности
```

### 39 - зона тумана и ambient

```
sphere bound
float  ambient        // серый
int    unused
float  fogStart
float  fogEnd
int    fogColor       // индекс в палитре; < 0 - туман выключен
int    childCount
list
```

Действует на собственных детей.

### 40 - генератор

```
sphere bound
name   collision     // "$$..." - код-генератор, иначе ссылка на блок
name   render        // ссылка на колбэк отрисовки
params               // как у примитивов коллизии
```

Колбэки `$$...` регистрирует код игры: `$$TreeGenerator`, `$$TreeGenerator1`,
`$$SeaGenerator`. Генератор создаёт геометрию на лету (деревья, море).

### 41 - комната с лайтмапами

```
float  minX, maxY, maxX, minY    // границы планарной проекции лайтмапы
int    lightmapCount
int    material[lightmapCount]   // используются первые 2
int    childCount
list
```

Без `bound`.

`STOS` в `ENV/aa.b3d`, сокращённо:

```
[5] STOS
  [37] Facia_5   режим 3, яркость 1.0     - кромка навеса, светится всегда
    [35] mode 3, stos_lrepair
  [37] Column_2  режим 2                  - стойки, освещаются
    [35] mode 3, stos_brick
  [10] LOD по сфере
    список 0 (близко):
      [21] refer_ILLUM_LEVEL_14           - окна: день / ночь
```
